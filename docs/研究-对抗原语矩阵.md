# 研究笔记：对抗原语增强矩阵 v1

> 状态：新原语已实现并用判重代理基准完成首轮打分。

## 1. 新增原语

- `transform/video.per_shot_retime`：逐镜头 0.95~1.08 倍微变速，叙事顺序不变。
  比全片统一变速更能打散时间轴对齐。
- `transform/video.cut_jitter`：镜头首尾随机去掉 0~4 帧，轻微漂移切点，
  破坏结构指纹的切点序列。
- `transform/audio.remix_strong`：变速 + 变调 + 强 EQ 倾斜 + 底噪，
  针对音频指纹的时间-频率对齐做双重扰动。
- `evaluate/attack_matrix.py`：双目标打分驱动（判重风险 × 画质/叙事连续性）。

CLI：

```bash
uv run --project backend cthulhu attack-matrix <短片段> --out-dir <目录> [--reuse]
```

## 3. 解读

1. 逐镜头变速 + 切点漂移 + 强音频重混把代理判重风险从 0.98 压到 0.35~0.45，
   图像与音频两维都产生了可测量距离。
2. 对齐 SSIM 是保守下界：逐镜头变速使帧映射非线性，搜索窗口 ±4 帧仍可能
   错配；真实观感优于该数值。叙事连续性 0.94~0.98，顺序未被破坏。
3. 强档的 SSIM 明显低于轻+，符合“研究/极限”定位；面向日常的档位应在
   轻+ 与 强 之间再取一点（预计风险 0.40 附近、SSIM ≥0.7）。

## 5. GUI 管线接入（2026-08-24）

逐镜头变速、切点漂移与强音频重混已接入清洗管线：

- `services.run_desensitize` 新增 `shot_retime / shot_retime_min/max /
  cut_jitter / audio_strong` 参数；
- 变速路径改为 O(N) 流式逐镜头映射（每个镜头只 seek 一次），不再逐块随机
  访问解码；快路径（speed=1、无新原语）保持原有流式实现；
- GUI 指纹对抗预设映射：标准=逐镜头变速+切点±2+强音频，强力=切点±3，
  全兵器=切点±4；
- 端到端回归：30s 1080p 片段，标准档组合输出判重风险 0.30（低）、
  pHash 距离 0.255、音频距离 0.392，叙事连续性稳定；快路径无回归。

速度说明：逐镜头变速与全局变速共用同一 O(N) 流式路径，未引入额外复杂度；
当前长片耗时仍受 1080p 软件编码与降噪等基础开销限制，与本批原语无关。

## 6. 候选排序接入代理基准（2026-08-24）

- `services.generate_candidates` 在生成每个候选后调用代理基准，写入
  `duplicate_risk`，评分公式升级为：0.55×内容保持 + 0.25×稳定性 +

- 前端候选列表展示判重百分比；评分失败不影响候选生成。
- 端到端验证：30s 片段两个候选判重风险 0.335/0.341，按低风险高画质排序。
- 指纹对抗档文案同步说明新能力：标准=逐镜头变速+强音频。

## 7. 泛化性观察（第二支片段，2026-08-24）

在 0702 另一支 30s 片段上复跑矩阵（单种子）：

| 预设 | 0608 风险 | 0702 风险 | 差异 |
| :--- | :--- | :--- | :--- |
| 轻+ | 0.394 | 0.687 | 大 |
| 强 | 0.268 | 0.511 | 大 |

结论：单种子、单片段、24 帧采样窗口的代理分数对内容节奏高度敏感，
尚不能作为三档参数的绝对标尺。GUI 当前映射（0.98~1.04 逐镜头变速、
切点 ±2/3/4）保持保守值；正式标定需要多片段 × 多种子取均值，并用平台
判重真值修正锚点。
