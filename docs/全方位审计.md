# 软件全方位审计（结合暗水印对抗领域认知）

> 审计日期：2026-08-19
> 范围：docs（PRD / 实施文档 / UI 审计 / 样式 demo）+ ui（React 前端）+ electron（桌面壳）+ backend（Python 后端）
> 方法：以 PRD 为需求基线，加入暗水印攻防领域认知，从正确性、覆盖面、产品、UI、架构、性能、数据安全七个维度审计。

## 一、现状基线

- 前端：M1 完整（五视图、导入、预览、区域、报告、队列、模板、历史、设置、双主题、Claude 主题 + shadcn/ui）。

## 三、领域正确性审计（对抗暗水印认知）

### 3.1 PRD 算法假设无法验证，不能作为基线

PRD 第六章以「已验证结论」口吻给出抖音频域水印具体参数（Zigzag 12~35 位、QIM 步长、16 帧同步块、128bit 载荷、卷积码生成多项式）。但仓库内没有任何样本、差分记录或实验数据佐证。真实平台嵌入参数是保密的，且嵌入发生在平台转码阶段、与编码器量化决策纠缠：

- 解码后的 DCT 系数是「嵌入值 × 编码量化」的产物，无法直接反推嵌入量化步长；
- 「量化表指纹」在真实场景会被码率/CRF 选择掩盖，85% 匹配度阈值无依据；
- 16 帧信息块周期若存在，应通过互相关/谱估计从数据估计，而不是写死窗口。

处理：把 PRD 全部算法数字降级为待验证假设（实施文档已声明），并为每个假设建立对照实验。

### 3.2 检测覆盖缺口

现有计划覆盖 LSB / DCT-QIM / DWT / 帧间 / 音频指纹 / 盲检测。按领域常见水印方案补盲：

| 水印类型 | 现状 | 应补的检测手段 |
| :--- | :--- | :--- |
| 空域扩频（加性 PN） | 无 | 残差与本地 PN 序列相关 + 多帧累积提 SNR |
| 低嵌入率 LSB/隐写 | 熵 + 直方图 | 增加 SPAM / 富模型类隐写分析特征 |
| DCT 域 QIM | 余数双峰 | 解码→同参重编码→差分得到编码噪声基准，测系数余数相对偏离 |
| 帧间时序 | 固定 16 帧自相关 | 多尺度周期估计（互相关 + 谱峰）定位同步码周期 |
| 音频回声隐藏 | 无 | 倒谱域回声峰检测 |
| 音频相位编码 | 无 | 相位连续性 / 相位直方图分析 |
| 码流层特征（压缩域） | 无 | 不解码直接分析 H.264 残差系数统计、宏块 QP 模式、运动矢量奇偶 |
| 容器/文件层 | 仅 SEI | udta/meta/XMP、附加 trak、文件尾附加数据、MD5/关键帧关联库比对 |

### 3.3 清除与对抗方法缺口

PRD 的系数收缩、量化域偏移、伪水印注入是合理起点，但缺几类高性价比攻击：

| 方法 | 说明 | 效果 |
| :--- | :--- | :--- |
| Wiener / BM3D / NLM 去噪 | 空域滤波 | 对 SS、LSB 极有效，画质可控 |
| 重量化 / 换编码器重编码 | 改变 QP 或 x264→x265 | 对 QIM/DCT 类常优于系数收缩 |
| 几何攻击 | 裁剪 2~5% + 缩放 99~101% + 旋转 0.3~1° | 破坏块对齐与同步码 |
| 变速攻击 | 0.9~1.1x 重采样（音画同步） | 破坏帧间时序同步 |
| 协同平均（多副本） | 同一素材多个不同水印副本求平均 | SS/LSB 近乎无损消除，性价比最高，PRD 未提 |
| 音频处理 | 现状仅「频谱轻微处理」 | 补 0.5~1% 变速保音高、相位随机化、EQ 微调、回声抑制 |

以上为研究口径的攻击技术枚举，用于评估鲁棒性或处理自有/授权素材，落地需遵守第 8 节边界。

### 3.4 评估闭环的根本问题（最高优先级）

PRD 的「清除率 95%」「BER>80% 判有效」隐含拥有平台真实提取器，现实中没有。用自研逆向解码器测 BER 是循环验证——自己的解码器解不出，不等于平台的解不出。

正确做法：

1. 自建参考水印基准库：自己实现 QIM / DCT-SS / LSB / 回声隐藏等标准嵌入器，生成干净-带水印配对样本。
2. 对每个攻击算法输出 BER / 鲁棒性矩阵（压缩、几何、噪声、时序各维度）。
3. 指标升级：VMAF（比 PSNR 更贴合投流画质感知）、时域闪烁度量、码率变化、吞吐 P50/P95、相似度下降幅度。
4. 平台侧黑盒实测只作为最终验证，不作为迭代手段（成本高、周期长、有合规风险）。

### 3.5 主矛盾识别：内容指纹 > DCT 水印

demo 计划第 2 节已正确指出：内容指纹（关键帧/MD5/多模态 embedding 相似度）与水印相互独立，且是搬运判定的主力。PRD 把重心放在 DCT 水印上，低估了内容指纹。应把「内容脱敏」提升为一级能力模块：

- 分镜重排、变速、重新构图（裁剪/画中画）、重调光/调色、字幕/贴纸、音频替换与重混；
- 用自建 embedding 相似度量化「与源相似度下降」，让效果可测；
- 诚实标注：深度二创仍可能保留暗水印信号，内容指纹无法完全消除，只能降低命中概率。

## 五、UI/UX 增量审计

- 检测报告的命中维度四行是静态的，不随素材风险联动。
- 缺平台选择器（影响特征库匹配与报告解读）。
- 水印区域卡缺时间范围（PRD 3.1.2 + demo 计划起止时间）。
- 预览区缺放大/局部对比交互（「双击放大」目前只是文案）。
- 音频处理无波形/频谱可视化。
- 设置页缺：日志目录、特征库自动更新开关、临时目录清理策略。
- 导入弹窗浏览器可用；桌面端需接 Electron 文件路径桥。

## 六、架构与工程审计

1. 后端空壳：仅 health/ws，无 import/detect/remove/evaluate 模块、无错误码、无进度协议。M2 起需定义 REST 命令 + WS 事件完整契约。
2. 桌面文件路径：Electron 拖拽的 File 对象拿不到完整路径，需 webUtils.getPathForFile 经 IPC 传给 Python。
3. 本地服务安全：固定端口 57173 无鉴权，任何本地进程可调 API，建议随机端口 + 一次性 token。
4. 无测试：前端无 Vitest，后端无 pytest；DCT/QIM/评估等高风险纯函数必须单测。
5. 无 CI：typecheck/build 靠手动。
6. 打包未实现：PyInstaller + electron-builder、ffmpeg/模型资源清单缺失。
7. SQLite 仅计划：无 schema/迁移；任务、模板、审计、设置、实验注册都依赖它。
8. 特征库无文件格式、签名校验、版本与增量更新设计。
9. CLI 缺失：研究期跑对照实验矩阵、批处理、样本制备，CLI 比 GUI 高效，建议 M2 先落地。
10. 日志：无结构化日志与导出实现。

## 七、性能

- PRD 的「1:1.5 速度、100 路并发」在无算法实现前无法评估，应改为吞吐 P50/P95 + 峰值内存的可复现指标。
- 4K/10GB 输入需明确：分段解码 + 帧滑动窗口 + 关键帧索引寻址（时间轴拖动、断点续传都依赖）。
- GPU/Metal/VideoToolbox 硬件编解码未实现，仅预留开关。
- 频域逐帧 DCT 是热点：先向量化，必要时 Numba，最后才考虑 PyO3 内核。

## 八、数据、安全与边界

- 样本属敏感内容：data/ 已入 .gitignore；采集应登记来源，只用自有/授权/合法公开样本。
- 本地 API 加 token。
- 处理日志含路径与参数快照，属审计留痕，导出时明确「仅本机使用」。
- 合规边界：私有研究工具不对外发布；PRD 中「规避平台治理/矩阵关联处罚」类表述不进入产品文案；搬运判定相关功能以降低误判风险、处理自有/授权素材为边界。

## 九、建议的下一步优先级

1. M2 样本先行：样本采集/制备 CLI + 自建参考水印基准库（QIM/SS/LSB/回声隐藏嵌入器），打通「样本 → 检测 → 攻击 → BER/VMAF 评估」最小闭环。
2. 检测与清除按盲区清单补齐（3.2/3.3），先空域 SS + 回声 + 压缩域，再做重量化/去噪/变速。
3. 内容脱敏模块立项（3.5），配 embedding 相似度量化。
4. 工程债随 M3–M6 偿还：文件路径桥、API token、pytest/vitest、SQLite 迁移、打包。
