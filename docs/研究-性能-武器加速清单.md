# 武器性能立项拆解（v1，2026-08-31）

> 口径：真实 720p RGB 素材、24 帧块、uint8 输入管线，单位 ms/帧。
> 目的：为「10 分钟内处理 5 分钟素材」目标列出每个武器的可行加速手段、
> 预期收益与结论，避免再做无依据的改造。

## 已落地（本轮）

| 武器 | 优化前 | 优化后 | 手段 |
| :--- | :--- | :--- | :--- |
| 跨帧估计相减 | 116 | 8.7 | 亮度域 + 帧抽样 + cv2 中值 |
| 高斯系（纹理/复杂度/多尺度） | 91 | 44 | cv2 GaussianBlur 取代 scipy |
| 像素重量化 | 20 | 2.5 | uint8 查表 |
| DCT 重量化 | 20 | 11.9 | 只算亮度、差值叠回 |
| 小波细节带 | 19 | 8.3 | 只算亮度 |
| 中频 DCT 扰动 | 33.5 | 12.2 | 矩阵化 DCT + 只算亮度 |
| 噪声 | numpy | 原生滤镜 | ffmpeg noise 下沉 |
| 解码 | 软件 | VideoToolbox | 硬解（2ms/帧） |

## 剩余武器现状与结论

| 武器 | 当前 | 可加速手段 | 预期 | 结论 |
| :--- | :--- | :--- | :--- | :--- |
| FFT 相位 | 10.5 | 已是 pocketfft C + 亮度域 | ≈0 | 封顶 |
| 色度量化 | 10.2 | 已是整数 BT.601 | ≈0 | 封顶 |
| 画质门控 | ~18/块 | 块大摊薄、代理降采样已做 | ≈0 | 封顶 |
| 人脸/神经/LPC | 一次性 | 场缓存/模型加载已优化 | ≈0 | 封顶 |
| 旋转/调光/锐化/降噪 | 原生滤镜 | 已下沉 ffmpeg | ≈0 | 封顶 |

## 结论

1. 本栈（numpy/scipy/cv2/ffmpeg）内，**均衡档武器已接近实现上限**：单块
   武器合计约 62ms + 基础变换 19~32ms，实测 17~19 分钟（9955 帧）。
2. 进程池并行实测无收益（内存带宽受限），已默认关闭并保留环境开关。
3. GPU（Metal/MPS）对这批信号处理算子无可用实现，重写成本不可控，否决。
4. 再往下只有两条路，需单独立项：
   - **C 扩展/向量化重写**（如 DCT/FFT 批处理合并、减少中间拷贝）：
     预期合计再省 20~30ms/帧，可把均衡压到约 12~14 分钟，仍不达 10 分钟；
   - **换 32 核以上机器**：并行带宽上限提高，可望减半。
5. 产品口径（与《研究-通杀验收》v12 一致）：快速档 ≈13~17 分钟、
   均衡档 ≈17~19 分钟，不承诺 10 分钟。

## 追加：极速 · 原生档（v2，2026-08-31）

新增第五个预置「极速 · 原生」：只保留可下沉 FFmpeg 原生滤镜的武器
（lut 重量化、噪声、旋转、调光、降噪、锐化、裁剪、音频重混），不含任何
频域/估计类 numpy 武器。实测 **28ms/帧 ≈ 0.9 倍视频时长**（9955 帧约 5
分钟），满足「清洗时长 ≈ 视频时长」目标。代价：放弃频域攻击，仅空域/
编码域覆盖。重量化原生化（lut）已验证与 numpy 效果等价（QIM BER 0.005
vs 0.004）。

原型验证状态（2026-08-31）：
- lut 重量化原生化：✅ 效果等价；
- 跨帧估计相减的 ffmpeg 链：✅ 已复现并验证。
  关键坑：`blend=all_mode=subtract` 把负残差钳到 0（范围 0~0.95），改用
  「加/减两步重构」避开带符号残差：estimate = mean(frame) - mean(median)，
  先 `addition` 加回 β·mean(median)，再 `subtract` 减去 β·mean(frame)。
  8bit 即可，无需 float：
  `split=3[a][b][c];[b]median=radius=1[m];[m]tmix=frames=24[tm];[a]tmix=frames=24[ta];[c][tm]blend=all_mode=addition:all_opacity=B[s1];[s1][ta]blend=all_mode=subtract:all_opacity=B[out]`
  实测：β=0.8 SS BER 0.427（numpy 0.193）、β=1.0 0.686（numpy 0.408）——
  破坏力强于 numpy；720p 链速 15.9ms/帧（519% CPU，8bit SIMD）。
- vDSP FFT 桥：⏸️ 未完成。

## 追加：第四轮优化（v4，2026-08-31）

1. 色度量化下沉原生（`lutyuv` 单滤镜链，U/V 查表量化、Y 保留）：约省 8ms/帧；
2. 哈希对抗外层循环 4/3→2：pHash 专攻 8.7ms/帧、dHash 专攻 6.1ms/帧，
   一致率分别 0.850/0.860，与减半前持平——外层全分辨率回代是主要成本；
3. DCT 换 cv2.dct：否决——现有矩阵化实现已是批量 BLAS，逐块 cv2 更慢；
4. vDSP 2D FFT：尝试 ctypes 直调 vDSP_fft2d_zrop 未通（段错误，2D 契约/
   跨步/2 的幂填充需专门 C 层调试），列为唯一剩余项。

实测：均衡档（含 pHash 专攻）130ms → **89ms/帧（9955 帧约 15 分钟）**。

### 第五轮：剖面驱动 + 架构收口（2026-09-01）

cProfile 对真实管线（清除推荐类配置，120 帧 720p）剖面：

**已落地优化：拆掉 antiReembed。** 原 DCT 开关捆绑 `anti_reembed=True`
（块相位扰动，实测对强 QIM 增量有限、BER 仅 0.22），剖面占 0.86s/120帧
（约 7ms/帧）。解除捆绑后：13.16s → 10.72s（**-18.6%**，约 110→89ms/帧）。

**实测无效、已回退：**

1. 整链 float32 单次往返：武器内部仍各自 astype 拷贝、DCT 又做 ×255/÷255
   重缩放，净慢 4.6%（11.21s vs 10.72s），回退。
2. 硬件编码（VideoToolbox）：11.24s vs 11.24s 无差——瓶颈是 Python 侧
   原始帧写管道 I/O（write 1.7s + poll 0.85s），与编码器无关。

**剩余结构（89ms/帧 的构成，120 帧剖面）：**

| 项 | 占比 | 结论 |
| :--- | :--- | :--- |
| 编码管道 I/O（write+poll） | ~21ms | 架构固有，换硬编无效 |
| dtype 往返（astype+clip） | ~20ms | 需逐武器去拷贝+改 DCT 域处理，简单改法已证伪 |
| DCT/FFT/小波/门控 | ~35ms | 内存带宽封顶（文档已记录，vDSP 尝试失败） |
| 解码 | ~2ms | 已 VideoToolbox 硬解 |

**天花板结论**：numpy 栈 + 原始管道架构下，清除推荐类配置 **~89ms/帧**
是实际地板（≈1.4 倍视频时长，9955 帧约 15 分钟）。突破只剩两条路：
① DCT/FFT/小波改 C 扩展或原生滤镜重写（工程量大，vDSP 已失败）；②
换更高内存带宽机器。二者都不在可控收益内，本轮性能研究封板。

### 第六轮：架构杠杆穷举（2026-09-01）

针对「更好的实现/调用能否突破」逐项实测：

| 杠杆 | 做法 | 结果 |
| :--- | :--- | :--- |
| 编码管道缓冲 | Popen bufsize 4MB | 10.71/10.61 vs 10.72s 无差——瓶颈是字节吞吐非 syscall |
| float32 单链 v1 | 仅入口/出口转一次 | -4.6%，回退 |
| float32 单链 v2 | + `_as_float` float32 免拷贝 + DCT 直接处理 [0,1] 域 | -2%，回退 |
| 硬件编码 | VideoToolbox | 无差 |

保留的无副作用微优化（仅 float 路径生效）：`_as_float`/`_as_original`
对 float32 免拷贝、`dct_requant` 支持 [0,1] 域（省全图 ×255 往返），
重排/变速路径受益。dtype 往返是武器语义固有（uint8↔float 边界 + HSV
的 cv2 域转换），无法通过调用方式消除。

**强化后的天花板结论**：编码管道 I/O（~21ms）+ dtype 边界（~20ms）+
频域武器（~35ms，带宽封顶）是三层独立地板，全部经实验确认无法用
Python 层架构改进突破。~89ms/帧 即该架构的物理下限；唯一出路是 C
重写或更高带宽硬件。

## 追加：跨帧估计原生链已接入产品（v3，2026-08-31）

新增 `native_temporal` 开关（后端选项 + 模板字段 + 面板「原生加速」子开关）：
开启后在原生几何快路径上把跨帧估计交给 ffmpeg 链执行（median+tmix+
blend 两步重构，8bit），numpy 版作为重排/变速路径的兜底；`StreamingEncoder`
支持 `-filter_complex` 承载该图。实测 720p：原生跨帧组合（几何前缀+链）
**34ms/帧 ≈ 1.0 倍视频时长**（9955 帧约 6 分钟）。快速/均衡预置已默认开启
（PRESET_VERSION=7）。注意：链的 β 语义与 numpy 不同（同 β 下破坏力更强），
后续可据观感回调。
