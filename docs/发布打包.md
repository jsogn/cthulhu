## 2.2 潜空间净化运行时与权重（开箱即用）

- 运行时（torch/diffusers/transformers/accelerate/safetensors/huggingface-hub/
  tokenizers/tqdm）由 `backend[purify]` 提供，`pnpm package:backend` 与
  `pnpm dev` 都会带 `--extra purify`；PyInstaller spec 会 collect 这些包，
  缺失时直接构建失败而不是产出“净化永远回退”的包。
- 权重随包内置：`pnpm package:model` 把 TAESD（`madebyollin/taesd`，约 10MB）
  准备到 `packaging/models`，PyInstaller spec 将其放进 sidecar 的 `models/`，
  冻结态由后端通过 `sys._MEIPASS/models` 自动定位（PyInstaller 6 one-folder
  实际位于 `resources/backend/_internal/models`）；安装后零下载。
  `stabilityai/sd-turbo`（约 2.4GB）与扩散引擎已移除（research §19.1~19.3：
  清除率持平、保真度更高、快约 50 倍）。
- 构建前必须先生成内置模型，spec 缺失时会直接失败；CI 用
  `actions/cache` 缓存 `packaging/models`，避免每次构建重复下载。
- 安装包体积主要由运行时决定（约 1GB），权重本身只有约 10MB。
- **实机验证（2026-09-11）**：`pyinstaller packaging/cthulhu-backend.spec` 本机跑通，
  产物 `packaging/backend-dist` 共 **1.0GB**（删除 sd-turbo 前会是 3.4GB 量级）；
  冻结态启动后 `/api/purify/status` 返回 `bundled=true / cached=true / state=ready`，
  权重路径解析到 `_internal/models/madebyollin--taesd`，证明内置权重在打包产物里可用。
  仍未验证：electron-builder 出 dmg（签名/公证另见下节）。
- 开发/自托管环境没有内置模型时才允许兜底下载
  （`CTHULHU_PURIFY_ALLOW_DOWNLOAD=0` 可关闭），带磁盘预检与进度。

## 6. 云端 CI 构建（已配置）

`.github/workflows/package.yml` 提供三平台矩阵打包：推送到 GitHub 后，
在云端并行构建 Apple Silicon mac（dmg）与 Windows（nsis）安装包，
自动完成依赖安装、静态 FFmpeg 下载、前端构建、PyInstaller sidecar 与
electron-builder 打包，产物作为 Actions artifact 下载。

- 触发方式：`git tag v0.1.0 && git push origin --tags`，或在 Actions 页面手动
  Run workflow。
- Intel mac 无云 runner（GitHub 已退役 Intel 机型），需在本地 Intel mac 上执行
  `FETCH_PLATFORM=darwin-x64 bash packaging/fetch_ffmpeg.sh && pnpm package`。
- 云端 PyPI 走官方源（workflow 内覆盖），本地开发仍用清华镜像。
- Windows 构建机无需手动下载 ffmpeg：脚本的 win64 分支自动从 BtbN 获取。

## 7. 本地出包与打包后冒烟（2026-09-11 实测）

```bash
pnpm package                     # 前端 → PyInstaller sidecar → electron-builder dmg
# 只重建 sidecar（改 backend 后最快的验证路径）：
pnpm package:backend
```

两条踩坑记录：

1. **electron-builder 首次下载会卡 GitHub**：出现
   `Timeout awaiting 'request' for 600000ms` 时用国内镜像重试即可，无需改配置：

   ```bash
   export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
   export ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
   pnpm --dir electron dist
   ```

2. **运行期依赖必须带 dist-info**：PyInstaller 只给 `collect_all` 过的包拷贝元数据，
   而 `diffusers/dependency_versions_check.py` 在 import 时会用 `importlib.metadata`
   校验 `requests` / `filelock` / `numpy` —— 缺 `requests` 元数据会让 diffusers
   导入失败、净化引擎**静默降级**（`purify_note: "fallback: ... requests ..."`，
   界面上只看到一句降级说明）。`packaging/cthulhu-backend.spec` 已用
   `copy_metadata("requests")` 补齐；再加运行期依赖时留意同类校验。

打包后冒烟（不装 App 也能验最关键的冻结链路）：

```bash
SIDE=packaging/backend-dist/cthulhu-backend
CTHULHU_DB=/tmp/cthulhu-smoke/cthulhu.db CTHULHU_AUTH_TOKEN=token \
CTHULHU_PORT=57998 CTHULHU_FFMPEG_DIR=$PWD/packaging/ffmpeg \
  "$SIDE/cthulhu-backend" &
curl -s localhost:57998/api/health
curl -s -H 'X-CTHULHU-Token: token' localhost:57998/api/purify/status   # bundled=true/state=ready
```

再发一次带 `purify_strength>0` 的 `/api/desensitize`，确认返回
`purify_note: applied (潜空间重建...)` 而不是 `fallback`：这一步能同时验证
内置权重、torch/diffusers 冻结导入与 ffmpeg 内置路径。
